Custom DeepSeek Stack

A frontier-class model, rebuilt to our own specs and served on our own hardware.

Why this project exists

This was never about building the fanciest thing for its own sake. It was about two hard problems, and neither one had a clean answer waiting for us.

First: DeepSeek-V4 didn't have vision, and the model is too big to run a separate vision model alongside it. Some people grafted on Kimi's vision tower, but that made the whole thing too big to serve comfortably. So I found a smaller vision tower made to graft onto it, and I did it.

Second: once we had a working DeepSeek model with vision, there was no inference provider built to run it. The grafting breaks speculative decoding - you're stuck at 10 tokens per second if you're lucky. So we had to build our own runner.

The model

We started from an abliterated DeepSeek checkpoint we were already running, and grafted a separate vision tower on top of it. The vision tower added less than 1 gigabyte in size. It worked - but there were a few points where the model wasn't as crisp in execution as I'd like.

Then a newer, much narrower abliteration came out. I didn't really care about having zero refusals - I cared about it executing well. So we grafted the same vision tower onto that newer base instead. The difference was real. It's hard to put a number on it, but orchestration, tooling, and coding all felt tighter. It was immediately more capable and coherent.

This is a component composition, not weight averaging. The language shards stay byte-identical to their source; the vision tower and projector load separately and the custom runtime inserts the image embeddings at the image token. The result is a vision-capable model we can actually serve.

The runner

Because no standard inference provider could run a grafted-vision DeepSeek, we built our own. That meant working inside the deep end of the pool: distributed inference on dual DGX Spark nodes, where the hard problems live.

The first version took a community fork of vLLM built for DeepSeek on this hardware as its base and patched in vision support. It worked. We then went back and rebuilt it from the same base, folding in every performance update from the leading DGX fork plus the vision patches, to get to a second version that was materially better.

We're not done. There are much newer versions of vLLM out now with better DeepSeek support and newer CUDA driver usage. We have a working version built on vanilla vLLM 27.2 with the specific DGX updates and the vision add-on folded in, running on the Marlin backend instead of the older one. It should be faster. We don't have enough data yet to know if that's actually true, so we're testing it before we claim anything.

The stack

NVIDIA DGX Spark hardware (dual-node for the DeepSeek stack), custom vLLM builds for local inference, and a community fork of DeepSeek-V4 with a grafted vision tower. The runner is served through a custom vLLM overlay with the vision plugin and DeepSeek-specific tuning.
