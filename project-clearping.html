ClearPing

Automatic background removal with a full editing workflow, built on our own spec and stack.

What it is

ClearPing does one thing well: takes an image with an unwanted background, removes it, and hands back a clean transparent PNG. From there it has a full workflow to edit the result - so you're not stuck with a one-click output you can't refine. It's deliberately narrow. It is not a full design tool, and it isn't trying to become one.

Access is invite-only with a magic link sign in, which keeps the app clean and private by design. There's a separate admin surface for managing users and invites, with operational visibility over how the service is running.

Visit ClearPing

The product

Release 1 is a narrow internal proof of concept: automated background removal, preview, download, strict temporary-file cleanup, and a small admin surface for access control and operational visibility.

Release 2 is the first real-user-testing release. It adds an editing layer - remove or restore specific regions, with a responsive editor that changes layout by screen size. Desktop uses a focused zoom canvas; mobile uses a bottom-sheet layout. Every edit request is validated locally before it hits the worker, and each selected area is saved as its own edit with a final "send all edits" step. The goal is a light, focused experience, not a broad photo editor.

How it's built

The stack was chosen for fast execution, quality, and low operational overhead: React + TypeScript + Vite frontend with separate user and admin entry points, Supabase for magic-link auth, Postgres, and minimal temporary object storage, Vercel for thin API orchestration, and a provider adapter layer for the background-removal engine.

The product policy is private by default: no retained file storage, temporary assets deleted aggressively after download, untouched assets cleaned up after 20 minutes, short-lived signed URLs, and no raw images in logs. Accept JPG, PNG, WEBP under 10 MB. Keep it narrow.

This was built the way I want to keep building: the full product requirements and technical design were written in Notion first, then built with agents handling the heavy lifting. Automated testing ran through Playwright, followed by a manual QA cycle.

Why it exists

The purpose here was never just to ship a background-removal tool. ClearPing is the proving ground for a way of working - spec it fully, build it end to end with agents doing the heavy lifting, and own the result. It's still in progress, and it's exactly the kind of project that shows how I work.

The stack

React + TypeScript + Vite frontend, Supabase for auth and Postgres, Vercel for serverless API hosting, Resend for email, and a provider adapter layer for the background-removal engine. Hosted across Vercel and Oracle.
